Imager

A pure browser-based utility for creating bootable USB flash drives directly from ISO images using modern File System APIs.

How Direct Client-Side ISO Flashing Works

Traditionally, creating bootable installation media required third-party desktop applications (such as Rufus, BalenaEtcher, or `dd` terminal commands) because web browsers were strictly sandboxed from accessing raw local disk storage.

Imager leverages the modern W3C File System Access API (`window.showDirectoryPicker`) and chunked binary streaming (`ArrayBuffer` / `WritableFileStream`) directly inside your browser. When you select your ISO image and target directory:

  • Zero Server Uploads: Multi-gigabyte operating system ISO files (such as Linux distributions or recovery tools) are never uploaded to any remote server, saving hours of network bandwidth and ensuring total privacy.
  • Chunked Streaming Memory Efficiency: Instead of loading a 4GB+ ISO entirely into RAM—which would crash the browser tab—the engine slices the file into sequential 5MB blocks (`file.slice(offset, offset + chunkSize)`) and writes them directly to the destination stream.

Understanding Boot Sectors, MBR, and UEFI Partitioning

An ISO image (`.iso`) is an uncompressed sector-by-sector archival disk image structured according to the ISO 9660 or UDF filesystem standard. Why does writing exact blocks make a drive bootable?

  • Master Boot Record (MBR) & El Torito: Hybrid ISO images contain specialized El Torito boot catalogs and Master Boot Records embedded within the first 512 bytes (sector 0) of the image. When a PC powers on, the BIOS executes the machine code stored exactly in sector 0 to initiate the bootloader stage.
  • EFI System Partition (ESP): For modern UEFI firmware, the hybrid ISO includes a FAT formatted boot partition containing the `EFI/BOOT/BOOTX64.EFI` binary executable. When the raw sectors are streamed directly to the media without modification, the motherboard firmware immediately recognizes the valid partition table and boot payload.
