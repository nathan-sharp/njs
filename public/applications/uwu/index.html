Unified Wrapper Unit (.uwu)

The Unified Wrapper Unit (.uwu) is a lightweight container format designed to solve the "it works on my machine" problem by standardizing the packaging of application logic, static assets, and runtime dependencies. Unlike heavy virtualization engines, a `.uwu` archive achieves cross-platform portability through an embedded user-space interpreter called P.A.W.S. (Platform Agnostic Wrapper Service).

Install the Runtime (P.A.W.S.)

Just like you need a PDF reader to open `.pdf` files, your operating system requires the Platform Agnostic Wrapper Service daemon to mount and execute `.uwu` archives.

Windows Users
  1. Click here to download the `paws-setup.exe` installer.
  2. Run the installer or execute via PowerShell: irm https://njs.dev/media/paws/win_install.ps1 | iex
Linux and macOS Users
  1. Open your terminal application.

  2. Run the universal POSIX installation script:

    curl -L https://njs.dev/media/paws/linux_install.sh | bash

Verify installation by typing paws --version in your terminal. You should see: P.A.W.S. v1.2.0

Download Your Unit & Execution Modes

Download the application archive you wish to execute (e.g., `application.uwu`). P.A.W.S. supports two distinct packaging distributions depending on deployment constraints:

  • Lean Units (~1MB - 10MB): Contains only bytecode, assets, and manifest declarations. Requires the P.A.W.S. runtime installed on the host operating system to provide shared standard libraries.
  • Chonk Builds (~50MB+): Standalone self-extracting binaries bundled with an embedded micro-PAWS runtime. Chonk builds require zero prior host installation—you can double-click and run directly on completely bare-metal machines.

Container Architecture vs. Virtual Machines

Understanding how the Unified Wrapper Unit achieves high performance across heterogeneous OS kernels without hypervisor overhead:

  • User-Space Namespacing: Instead of emulating virtual CPU hardware or booting an entire guest operating system kernel (like VirtualBox or QEMU), P.A.W.S. utilizes host kernel features—POSIX `chroot` and Linux namespaces on Unix systems, and AppContainer sandboxing on NT kernels—to isolate filesystem access.
  • Zero-Copy Asset Mounting: When executed, `.uwu` archives are memory-mapped (`mmap`) directly into virtual address space. Assets and scripts are read read-only from the archive header instantly without extracting temporary files to disk, eliminating startup latency.
