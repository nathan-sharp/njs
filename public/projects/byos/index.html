Bring Your Own Storage (BYOS)

Zero-infrastructure app backends powered by personal cloud accounts.

"Bring Your Own Storage" (BYOS), also known as the "Unhosted Web Apps" architecture, is a paradigm where web applications rely entirely on the user's existing cloud storage accounts (such as Google Drive, Microsoft OneDrive, or Apple iCloud) to store application state, settings, and user data. This eliminates the need for developers to provision, manage, and scale backend databases.

Core Advantages

  • Zero Server Costs: Developers do not pay for database hosting, storage, or bandwidth for user data.
  • Reduced Liability: The app never stores user data on its own servers, significantly reducing the impact and liability of a data breach.
  • Data Sovereignty & Privacy: Users retain full ownership of their data within a cloud provider they already trust. They don't need to create new accounts or manage new passwords.

Implementation Guide

To implement a BYOS architecture, the application typically operates as a Single Page Application (SPA) utilizing OAuth 2.0 with PKCE (Proof Key for Code Exchange) to securely authenticate the user directly from the browser without a backend.

1. Google Drive (Application Data Folder)

Google Drive provides a hidden space specifically for application data. By requesting the https://www.googleapis.com/auth/drive.appdata OAuth scope, your application can read and write files to this hidden directory.

  • Files stored here do not clutter the user's main Drive interface.
  • Users cannot accidentally delete or modify these application configuration files.
  • When the user uninstalls or disconnects the app, the data can be automatically purged (depending on user action).

2. Microsoft OneDrive (App Root)

Through the Microsoft Graph API, applications can access a Special Folder known as the "App Root" (/drive/special/approot).

  • The application requests the Files.ReadWrite.AppFolder permission.
  • Upon the first access attempt, OneDrive automatically provisions a dedicated folder with your app's registered name inside an Apps directory.
  • This provides a clean, sandboxed environment for your application's JSON state or binary files.

3. Apple iCloud (CloudKit)

For web applications, Apple provides CloudKit JS, which interfaces with iCloud.

  • Private Databases: Use these for syncing user-specific application state across devices. Only the authenticated user can access this data.
  • iCloud Key-Value Storage: Ideal for lightweight configuration parameters and settings.

Architectural Challenges

While BYOS provides tremendous benefits, it shifts complexity to the frontend client:

  • Token Lifecycle Management: The SPA must securely handle OAuth access tokens, refresh tokens, and session expiration gracefully.
  • Conflict Resolution & Sync: If a user operates the app simultaneously on a laptop and a mobile device, the frontend must merge state changes and handle network latency.
  • Multi-user Collaboration: Sharing data between different users requires navigating complex sharing permissions via the cloud provider's API, rather than simple cross-tenant database queries.
